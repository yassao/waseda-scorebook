# 実装計画

一般公開は 2026年6月末を目標にする。  
7月の高校野球予選シーズンで、ベータ版として実用できる状態を目指す。

## 進め方

- まずは球場で使ってもデータが消えない状態を作る。
- 次に、入力とスコアブック表示のズレを減らす。
- その後、取り込み・書き出し・PDF・PWAを整える。
- 慶応式、クラウド共有、課金、AI APIは土台が固まってから進める。

## Phase 1: 保存JSONとローカル保存

最優先。  
これができると、球場での試用、後から編集、PDF、慶応式展開が進めやすくなる。

実装内容:

- `schemaVersion` と `appVersion` を含む保存JSONを作る。
- 現在の試合状態を `localStorage` に自動保存する。
- ページ再読み込み後に試合を復元する。
- JSONエクスポート / インポートを実装する。
- 既存の `state` と保存JSONの対応表を作る。

完了条件:

- ブラウザを閉じても試合が残る。
- JSONファイルでバックアップできる。
- 保存データに `schemaVersion: 1` と `appVersion` が入る。

## Phase 2: 入力とプレビューの安定化

球場で迷わず使うための改善。

実装内容:

- `次の打者に移る` の前に、打者・走者プレビューとスコアブックが一致するようにする。
- ボールカウントの記号を確実にスコアブックへ残す。
- 走者の標準進塁をプレビューへ即時反映する。
- 走者アウト後も、プレビュー上ではグレーアウト表示で履歴を残す。
- 過去セルをタップして、打者結果・走者結果・つぶやきを編集できるようにする。

完了条件:

- 四球、単打、犠打、FC、併殺などで、プレビューとシートのズレが少ない。
- 間違えても過去打席を修正できる。

## Phase 3: 入力UI整理

手動詳細入力を廃止し、標準入力に集約する。

実装内容:

- 画面下部の `手動詳細入力` を削除する。
- 足りない項目は `打球結果` や走者操作ダイアログへ統合する。
- `打球結果` は全画面ダイアログで選びやすくする。
- 野手番号は実際の守備位置に近い並びにする。
- 野手番号長押しで、前・左・右・上などの打球方向を選べるようにする。
- 走者結果は「標準と違う時だけ触る」UIに寄せる。

完了条件:

- 主要プレーをスクロールなし、または少ない操作で入力できる。
- iPhoneでポップアップが隠れない。
- 手動詳細入力なしでも主要ケースを入力できる。

## Phase 4: X / 日刊スポーツ取り込み改善

従来スコアアプリとの差別化ポイント。  
ただし最初は下書き生成として扱う。

実装内容:

- 日刊スポーツ取り込みを全画面UIにする。
- `先攻チーム取り込み`、`内容クリア`、`後攻チーム取り込み` に整理する。
- X取り込みを1イニング単位に制限する。
- 取り込み結果には原文コメントを吹き出しとして保存する。
- AI整形プロンプト生成を改善する。
- `ギ`、`邪`、`野`、`一塁はセーフ` などの解釈を強化する。

完了条件:

- 日刊スポーツの表をコピペして大まかなスコアブックを作れる。
- Xポストを1イニング単位で貼り付け、下書きとして反映できる。
- 取り込み精度が低い場合も、後から修正できる。

## Phase 5: PDF出力とX書き出し

初期の有料価値になりやすい機能。

実装内容:

- スコアブックをPDF出力する。
- 先攻・後攻を上下に並べた閲覧モードを整える。
- 吹き出しコメントを閲覧モードでも確認できるようにする。
- イニングごとのX投稿文を生成する。
- `#CuViu` を自動付与できるようにする。

完了条件:

- 1試合分をPDFとして保存できる。
- イニングごとの実況文をコピーしてXに投稿できる。

## Phase 6: PWAと公開準備

6月末公開に向けた仕上げ。

実装内容:

- PWA化する。
- オフライン起動に対応する。
- iPhoneホーム画面追加の案内を作る。
- `cuviu.jp/apps/scorebook/` への公開運用を安定させる。
- ベータ協力プログラム説明を作る。
- プライバシーポリシーを用意する。

完了条件:

- 球場で通信が弱くても、読み込み済みなら継続利用できる。
- ベータユーザーへURLを案内できる。
- データ提供は任意同意であることを明示できる。

## Phase 7: その後の拡張

一般公開後に進める。

候補:

- 慶応式表示
- クラウド保存
- アカウント認証
- Pro機能
- 広告非表示
- PDF高機能版
- チーム共有
- リーグ戦表
- 通算打率などの統計
- AI APIによる自動整形
- ローカルAI / 専用モデル

1. 保存JSONの初期実装
2. localStorage自動保存・復元
3. JSONエクスポート / インポート
4. 過去セル編集の入口
5. 入力UI整理と手動詳細入力の廃止
6. X / 日刊スポーツ取り込みの全画面化と精度改善
7. PDF出力
8. PWA化

## 5月中旬の目標

- 保存JSONの外枠を決める。
- ローカル保存を実装する。
- 入力UIの大きな方針を固定する。
- スコアブックの主要ルールを仕様ノートに反映し続ける。

この段階では、全プレーの完全対応よりも「消えない」「戻せる」「後から直せる」ことを優先する。
