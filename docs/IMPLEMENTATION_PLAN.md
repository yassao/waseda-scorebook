# 実装計画

一般公開は 2026年6月末を目標にする。  
7月の高校野球予選シーズンで、ベータ版として実用できる状態を目指す。

## 進め方

- まずは球場で使ってもデータが消えない状態を作る。
- 次に、入力とスコアブック表示のズレを減らす。
- その後、取り込み・書き出し・PDF・PWAを整える。
- 慶応式、クラウド共有、課金、AI APIは土台が固まってから進める。

## Phase 1: 保存JSONとローカル保存

状態: 完了（2026-05-14）  
以後は不具合や互換性問題が見つかった時に随時補修する。

最優先。  
これができると、球場での試用、後から編集、PDF、慶応式展開が進めやすくなる。

実装内容:

- `schemaVersion` と `appVersion` を含む保存JSONを作る。
- 現在の試合状態を `localStorage` に自動保存する。
- ページ再読み込み後に試合を復元する。
- JSONエクスポート / インポートを実装する。
- 既存の `state` と保存JSONの対応表を作る。

完了条件:

- ブラウザを閉じても試合が残る。
- JSONファイルでバックアップできる。
- 保存データに `schemaVersion: 1` と `appVersion` が入る。

## Phase 2: 入力とプレビューの安定化

状態: 着手中（2026-05-14開始）

球場で迷わず使うための改善。

実装内容:

- `次の打者に移る` の前に、打者・走者プレビューとスコアブックが一致するようにする。
- ボールカウントの記号を確実にスコアブックへ残す。
- 走者の標準進塁をプレビューへ即時反映する。
- 走者アウト後も、プレビュー上ではグレーアウト表示で履歴を残す。
- 過去セルをタップして、打者結果・走者結果・つぶやきを編集できるようにする。

当面の作業順:

1. 過去セル編集を `prompt` ではなく、専用ダイアログで選べるようにする。
2. 打者・走者プレビューとスコアブックの差分が出るケースを洗い出す。
3. 四球、単打、犠打、FC、併殺の順に標準進塁とアウトカウントを安定させる。
4. ボールカウント記号が保存・復元・編集後も消えないことを確認する。
5. 過去セル修正後に、塁上走者・アウトカウント・得点板が破綻しないようにする。

進捗:

- 2026-05-15: 過去セルをタップした時の編集選択を専用ダイアログ化。

完了条件:

- 四球、単打、犠打、FC、併殺などで、プレビューとシートのズレが少ない。
- 間違えても過去打席を修正できる。

## Phase 3: 入力UI整理

手動詳細入力を廃止し、標準入力に集約する。

実装内容:

- 画面下部の `手動詳細入力` を削除する。
- 足りない項目は `打球結果` や走者操作ダイアログへ統合する。
- `打球結果` は全画面ダイアログで選びやすくする。
- 野手番号は実際の守備位置に近い並びにする。
- 野手番号長押しで、前・左・右・上などの打球方向を選べるようにする。
- 走者結果は「標準と違う時だけ触る」UIに寄せる。

完了条件:

- 主要プレーをスクロールなし、または少ない操作で入力できる。
- iPhoneでポップアップが隠れない。
- 手動詳細入力なしでも主要ケースを入力できる。

## Phase 4: インポートと自然文入力の整理

従来スコアアプリとの差別化ポイント。  
ただし最初は「下書き生成」として扱い、後から修正できることを前提にする。

### 日刊スポーツ取り込み

目的:

- 終了済み、または進行中の試合について、日刊スポーツの表をまとめて取り込む。
- 1打席ずつではなく、複数イニング分をまとめてスコアブック化する。
- 途中経過でも取り込めるようにする。

実装内容:

- 日刊スポーツ取り込みを全画面UIにする。
- `先攻チーム取り込み`、`内容クリア`、`後攻チーム取り込み` に整理する。
- 選択打順からの一括取り込みは廃止し、原則として1番から自動配置する。
- 選手名は3段の名前欄に分けて反映する。
- 4人目以降は暫定的に3段目へ `/` 区切りで表示する。
- 複数イニングのアウトカウント、標準進塁、得点をラフに推定する。
- `ギ`、`邪`、`野`、`併` などの略記を解釈する。
- インターネットブラウザ、iPhoneブラウザの両方のコピペ形式に対応する。

完了条件:

- 日刊スポーツの表をコピペして、大まかなスコアブックを作れる。
- 先攻と後攻を分けて取り込める。
- 多少の誤りがあっても、後から編集で直せる。

### X / Twitter 取り込み

目的:

- 観戦者のXポストや実況メモを、1イニング単位で取り込む。
- 結果だけでなく、原文コメントも吹き出しとして残す。

実装内容:

- X取り込みを全画面UIにする。
- 1回の取り込みは1イニングに制限する。
- 複数イニングが含まれている場合は警告する。
- 前回取り込みの続きから配置することをデフォルトにする。
- 取り込み結果には原文コメントを吹き出しとして保存する。
- `一塁はセーフ`、`牽制アウト`、`暴投で進塁`、`挟殺` などの表現を段階的に強化する。
- 解釈困難な行は、コメント付きの下書きとして残す。

完了条件:

- 1イニング分のXポストを貼り付けて、打順に沿った下書きが作れる。
- 各セルに原文コメントの吹き出しが付く。
- 誤変換があっても、後から修正しやすい。

### 1人単位の自然文入力

目的:

- 従来の `詳細入力` の代替として、1打席だけ自然文で入力する。
- 将来の音声入力の受け皿にする。

実装内容:

- X取り込み画面の近くに `1打席入力` として配置する。
- 現在打者、または選択した過去セルに対して反映できるようにする。
- 例: `ショートゴロ内野安打`、`センター前ヒット`、`見逃し三振`。
- 常時表示のテキスト入力欄は廃止し、必要な時だけ使うオプションにする。

完了条件:

- 1人分だけ自然文で入力し、現在セルまたは選択セルへ反映できる。
- 通常のボタン入力と役割が混ざらない。

### AI整形プロンプト生成

目的:

- ユーザー自身がChatGPT、Gemini、Grokなどに貼り付けて、このアプリに取り込みやすい形式へ変換できるようにする。
- 将来のAPI連携、ローカルAI化、改善データ収集につなげる。

実装内容:

- AI整形プロンプト生成を改善する。
- 日刊スポーツ用、X 1イニング用、1打席用でプロンプトを分ける。
- `名前 結果 コメント` を1打者1行で出力するよう明示する。
- 出力例は匿名化する。
- 必要に応じて、整形結果の貼り付け先へ誘導する。

完了条件:

- 取り込み前にAI整形プロンプトを生成できる。
- 複数AIで破綻しにくい、明示的なプロンプトになっている。

## Phase 5: PDF出力とX書き出し

初期の有料価値になりやすい機能。

実装内容:

- スコアブックをPDF出力する。
- 先攻・後攻を上下に並べた閲覧モードを整える。
- 吹き出しコメントを閲覧モードでも確認できるようにする。
- イニングごとのX投稿文を生成する。
- `#CuViu` を自動付与できるようにする。

完了条件:

- 1試合分をPDFとして保存できる。
- イニングごとの実況文をコピーしてXに投稿できる。

## Phase 7: 入口体験と見た目の魅力

機能がある程度固まってから進める。  
ただし、一般公開前には最低限の入口体験を用意する。

実装候補:

- トップ画面を作る。
- `新しく入力する`、`過去の試合を見る`、`インポートする` を選べるようにする。
- 簡単なスプラッシュ表示を入れる。
- スマホ、タブレット、PCでレイアウトを切り替える。
- 着せ替えテーマを複数用意する。
- 有料版ではテーマ選択を開放する。
- 小さなアイコンやブランド表示を整える。

完了条件:

- 初めて開いた人が「何をすればいいか」迷いにくい。
- 使ってみたくなる雰囲気がある。
- 入力画面の邪魔にならない。

## その他の検討メモ

### 改善協力プログラム

- 7月末まではベータ協力期間としてPro機能を無料開放する案。
- 8月以降は協力者向けディスカウントを検討する。
- 変換ミスの改善データ送信は任意同意にする。
- 送信前に内容確認できるようにする。

### 収益化

- PDF出力、広告非表示、X書き出し、テーマ選択をPro候補にする。
- 広告はPDF出力や共有時のリワード広告を優先検討する。
- バナー広告は補助的に考える。
- 将来的にはアカウント紐づけで購入状態を管理する。

### 公式サイト

- `cuviu.jp` はWordPressでブランドサイトとして育てる。
- アプリ本体は `cuviu.jp/apps/scorebook/` に配置する。
- 将来、卓球スコアアプリや計測デバイスも並べられる構成にする。

### デザイン刷新

- 機能が固まったら、CSSやデザインシステムを見直す。
- WordPress風のレスポンシブ設計を意識する。
- スコアブックらしさと、スマホアプリらしさの両方を狙う。
