# スコアブック記号ルール

Scorebook by CuViu では、当面は早稲田式を主軸にする。  
記号ルールは BASEBALL ONE、パ・リーグ.com、スコアラー、長崎県高野連資料を参考にしつつ、最終的にはアプリ内の一貫性を優先する。

## 色の基本

- 黒: 通常のアウト、投球、補助記号
- 赤: 安打、長打、得点に関わる主要な進塁線
- 青: 犠打、犠飛、補助的な記録

## 投球記号

投球欄は左側の縦長長方形に記録する。

| 内容 | 記号 |
|---|---|
| 見逃しストライク | `○` |
| 空振りストライク | `×` |
| ボール | `・` |
| ファウル | `－` |
| バント失敗ストライク | `ギ` またはバント記号を添える |
| ファウル方向 | 捕手後方、右方向、左方向が分かる場合は補助記号で残す |

三振や四球はカウントから自動判定できるようにする。
ただし、詳細記号は必ずスコアブックに残す。

盗塁、盗塁刺、暴投、捕逸、ボーク、失策進塁など投球と同時に起きた走者イベントは、打席全体の走者記録に加えて、その時点の投球番号・B/S・直前投球記号を保存する。  
表示上も直前投球欄へ `S`、`CS`、`WP`、`PB`、`BK`、`E` などを補助メモとして残す。

現行アプリの内部表現や旧データに `●`、`△` などが残る場合がある。
新規描画は長崎県高野連資料の表記へ段階的に寄せ、読み込み時は旧記号も互換扱いする。

## 打球種別

| 内容 | 表記 |
|---|---|
| ゴロ | 守備番号の下に半円状のゴロ記号 |
| フライ | 守備番号の上にフライ記号 |
| ライナー | 守備番号の上に横棒 |

ファウルフライは `邪` を含む表記として扱う。

例:

- `三邪`: 三塁手が捕球したファウルフライ
- `捕邪`: 捕手が捕球したファウルフライ

## 安打

安打は赤線で到達塁まで記録する。

| 内容 | 到達線 |
|---|---|
| 単打 | 本塁から一塁 |
| 二塁打 | 本塁から二塁 |
| 三塁打 | 本塁から三塁 |
| 本塁打 | 本塁まで一周 |

守備位置番号と打球方向の点を記録する。

例:

- `8・`: センター前
- `7` の上に点: レフトオーバー
- `9` の横に点: ライト線方向

内野安打は、安打を半円で囲む。

例:

- サードへの内野安打: `5` + 下の点 + 内野安打の半円

バントヒットは `BH` を進塁線の左上側に記載する。

## 四球・死球

四球は `B` と赤の一塁進塁線で表す。  
遠四球・敬遠は `B'`、死球は `DB` として表示する。

旧実装で使っていた `W` は使わない。  
ルールに合わせて `B` に戻す。

## 犠打・犠飛

犠打は青色の四角で囲む。  
犠打は打数に含まれない。

例:

- `1-3`: 投手が処理して一塁送球
- `5-3`: 三塁手が処理して一塁送球

日刊スポーツなどの `ギ` は犠打として扱う。

例:

- `捕ギ`: 捕手が処理した犠打
- `投ギ`: 投手が処理した犠打

## アウト

アウトカウントは中央に `Ⅰ`、`Ⅱ`、`Ⅲ` で記録する。  
アウトカウントは、シート上の行順ではなく、イニング内のプレー進行順で付与する。

ゴロアウトは、捕球者だけでなく送球連携を記録する。

例:

- `6-3`: 遊撃手から一塁手
- `4-3`: 二塁手から一塁手
- `1-3`: 投手から一塁手

## フィルダースチョイス

フィルダースチョイスは `Fc` で表す。

例:

- 一走が二塁封殺、打者一塁セーフ: 一走側にアウト記録、打者側に `Fc`
- `4-6-3` を狙って一塁セーフ: 走者側に `4-6`、打者側に `Fc` と必要に応じて `6-3`

`封殺` はフォースアウトを意味する。  
進塁義務がない走者がタッチアウトになる場合は、封殺とは呼ばない。

## 併殺

併殺は `DP` を使う。  
複数セルにまたがる場合は、対象となる走者と打者が併殺であることを括弧や補助線で示す。

例:

- `6-4-3` の併殺
- `1-2-3` の本塁封殺から一塁併殺

「併殺」と「ダブルプレー」は同義として扱う。  
ただし「一塁はセーフ」とある場合は併殺ではなく、封殺 & FC として扱う。

## 進塁

打者結果による標準進塁は自動推定する。

例:

- 一走で単打: 一走は二塁へ標準進塁
- 一走で四球: 一走は二塁へ押し出し進塁
- 満塁で四球: 三走が生還

標準と違う場合は走者結果で上書きする。

例:

- 一走が単打で三塁へ進む
- 二走が単打で本塁生還
- 暴投で進塁
- 捕逸で進塁
- 送球エラーで追加進塁

追加進塁は、元の安打線とは別に黒矢印や補助表記で記録する。  
長打後のエラー進塁は、本塁打のように赤線を一周させない。

## 得点・残塁

得点は中央に赤丸で記録する。
自責点の場合は赤丸、非自責点の場合は白丸または資料の注記に準じる。

残塁はイニング終了時に残った走者のセルへ記録する。
資料では、得点・残塁のいずれかを中央や空欄に残し、打席マスを空欄にしないことが推奨されている。
保存JSONでは残塁を `left_on_base` イベントとしても残し、公式集計欄の残塁数へ反映する。
今後、残塁表記の細かな位置は資料に合わせて再確認する。

## 選手交代・投手交代

PDF資料では、試合中の守備位置変更や代打・代走は、その場面が分かるようにイニング間へ縦波線で記録する。  
代打は `PH` または `H`、代走は `PR` または `R` として扱い、どの回・どの場面で交代したかを残す。

投手交代は、打者マス側だけでなく下段の投手欄にも対応する。  
保存JSONではスターターを `officialSheet.pitchers` の `role: "starter"`、交代投手を `role: "relief"` として残し、交代時期を `enteredAt.inning`、`enteredAt.half`、`enteredAt.battingOrder`、`enteredAt.note` に保存する。  
イベント列にも `type: "substitution"`、`substitution.kind: "pitcher_change"` として出力し、将来のPDF出力で波線・投手欄・投球数欄を結びつけられるようにする。

画面表示では、投手交代ログの `enteredAt` に対応する打者マスへ青い波線と `P.投手名` を重ねる。
シート下段には投手欄を表示し、投方・氏名・勝敗・セーブ・投球回数・投球数・打者数を将来入力/集計できる枠として確保する。

## 失策

失策は誰のエラーかを明確にする。

| ケース | 表記例 |
|---|---|
| 三塁手の打球処理エラー | `5E` |
| 三塁手の送球エラー、一塁手へ | `5E-3` |
| 三塁手送球、一塁手の捕球エラー | `5-3E` |

エラーの種類:

- 打球処理エラー
- 送球エラー
- 捕球エラー

UI上は、ユーザーが迷いにくいように「野手1」「野手2」または「送球者」「捕球者」を整理する。

## 盗塁・盗塁刺

盗塁は走者セルに進塁として記録する。

例:

- 二盗
- 三盗
- 本盗

盗塁失敗は `盗塁死` または `二盗死` などの表記を解釈し、対象走者のアウトとして記録する。

送球やエラーが絡む場合:

- 捕手送球エラーで三塁進塁: `2E-5` など、送球先や失策者を記録
- 捕手から遊撃手への送球など、実際の連携がわかる場合は連携を優先

## 取り込み時の解釈ルール

### 日刊スポーツ

- `安`: 安打
- `２`: 二塁打
- `３`: 三塁打
- `本`: 本塁打
- `振`: 三振
- `四球`: 四球
- `死球`: 死球
- `ギ`: 犠打
- `邪`: ファウルフライ
- `併`: 併殺。ただし「一塁はセーフ」はFC扱い
- `野`: フィルダースチョイス

### X / Twitter

原則として1イニング単位で取り込む。  
複数イニングが含まれる場合は警告する。

`一塁はセーフ`、`一塁セーフ`、`セーフ` が連携や併殺表現と並ぶ場合は、併殺確定にしない。

## 慶応式への展開

保存データは早稲田式の図形そのものではなく、野球イベントとして持つ。  
そのため、将来は同じ `plateAppearances` と `events` から、早稲田式・慶応式の表示を切り替えられるようにする。

- 慶応式の記号ルール調査

- 表示専用レイヤーの分離
